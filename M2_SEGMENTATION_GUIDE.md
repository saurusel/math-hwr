# M2: Segmentation + MLP Guide

## 📚 Что такое M2?

**M2 (Segmentation + MLP)** - классический подход к OCR с сегментацией символов и классификацией перцептроном.

### Архитектура:

```
Input Image
    ↓
1. Segmentation (Connected Components)
   - Находит отдельные символы
   - Использует OpenCV connectedComponentsWithStats
   - Фильтрует по area (20-4000 pixels)
    ↓
2. Normalization
   - Resize каждого символа к 32x32
   - Padding и центрирование
   - Нормализация [0,1]
    ↓
3. MLP Classification
   - Input: 32x32 = 1024 пикселей (flattened)
   - Hidden: 1024 → 512 → 256 → 128
   - Output: num_classes (количество уникальных символов)
   - Dropout 0.3 для регуляризации
    ↓
Output Sequence
```

---

## 🆚 Сравнение с M1

| Аспект | M1 (CRNN-CTC) | M2 (Seg + MLP) |
|--------|---------------|----------------|
| **Подход** | End-to-end sequence | Character-by-character |
| **Сегментация** | Не требуется | Обязательна (connected components) |
| **Архитектура** | CNN + RNN + CTC | Segmentation + MLP |
| **Параметры** | ~1.5M | ~600K (меньше!) |
| **Скорость** | Быстрая (~50ms) | Зависит от числа символов |
| **Точность** | Хорошая для sequences | Хорошая для чистых символов |
| **Проблемы** | Сложные expressions | Касающиеся символы, шум |

---

## ✅ Преимущества M2:

1. **Интерпретируемость** - видно какой символ был распознан
2. **Простота** - понятная архитектура (сегментация + классификация)
3. **Малый размер** - меньше параметров чем M1
4. **Explicit segmentation** - можно визуализировать найденные символы
5. **Классический подход** - проверенная техника OCR

---

## ⚠️ Недостатки M2:

1. **Требует хорошей сегментации** - не работает с cursive/overlapping symbols
2. **Чувствительность к шуму** - артефакты могут стать "символами"
3. **Порядок важен** - предполагает left-to-right символы
4. **Потеря контекста** - каждый символ классифицируется независимо

---

## 🚀 Как использовать:

### 1. Создание M2 модели:

```bash
# Frontend: http://127.0.0.1:5174/train/new

Model Type: M2 (Segmentation + MLP)
Run Name: m2_test
Batch Size: 128 (больше чем M1, т.к. символы меньше)
Epochs: 10
Learning Rate: 0.001
Max Samples: 1000

Advanced Settings (опционально):
- Dropout: 0.3 (по умолчанию)
- Min Segment Area: 20 (минимальный размер символа в пикселях)
- Max Segment Area: 4000 (максимальный размер)
- Target Char Size: 32 (размер нормализации 32x32)
```

### 2. Мониторинг тренировки:

Метрики M2:
- **train_char_acc** - точность классификации отдельных символов
- **val_char_acc** - точность на валидации (символы)
- **val_seq_acc** - точность на полных выражениях (exact match)
- **val_seg_acc** - процент выражений где сегментация нашла правильное число символов

### 3. Inference в Playground:

M2 модели используют специальный endpoint `/api/predict_seg/run`:
- Автоматическая сегментация входного изображения
- Классификация каждого найденного символа
- Объединение в последовательность
- Возврат: prediction + число сегментов + детали каждого сегмента

## 📊 Ожидаемые результаты:

**На датасете synth (100 samples):**
- Train Char Accuracy: 85-95% после 5-10 epochs
- Val Char Accuracy: 75-90%
- Val Seq Accuracy: 40-70% (ниже из-за ошибок сегментации)
- Val Seg Accuracy: 60-80% (процент выражений с правильным числом символов)

**На полном датасете (96K samples):**
- Train Char Accuracy: 95-98%
- Val Char Accuracy: 90-95%
- Val Seq Accuracy: 60-80%
- Val Seg Accuracy: 70-85%

## 🔧 Настройка параметров:

### Segmentation параметры:

**min_seg_area** (default: 20)
- Минимальная площадь символа в пикселях
- Увеличить (50-100) если много мелкого шума
- Уменьшить (10-15) для мелких символов (точки, запятые)

**max_seg_area** (default: 4000)
- Максимальная площадь символа
- Увеличить если большие символы обрезаются
- Уменьшить если объединённые символы считаются одним

**target_char_size** (default: 32)
- Размер нормализации символа (32x32)
- Увеличить (64x64) для лучшего качества (больше параметров)
- Уменьшить (16x16) для скорости

### MLP параметры:

**dropout** (default: 0.3)
- Регуляризация для предотвращения overfitting
- Увеличить (0.4-0.5) при переобучении
- Уменьшить (0.1-0.2) при underfitting

## 🐛 Troubleshooting:

**Проблема:** Val Seg Accuracy низкая (<50%)
**Решение:** Символы плохо сегментируются. Попробуйте:
- Увеличить max_samples для более простых примеров
- Отрегулировать min/max_seg_area
- Проверить качество изображений (бинаризация)

**Проблема:** Train Char Acc высокая, но Val Seq Acc низкая
**Решение:** Overfitting или проблемы с сегментацией:
- Увеличить dropout
- Добавить больше данных
- Проверить согласованность train/val сегментации

**Проблема:** Model не обучается (accuracy не растёт)
**Решение:**
- Уменьшить learning rate (0.0001)
- Увеличить batch size (256)
- Проверить что segmentation работает (должна находить символы)

## 🎯 Когда использовать M2:

✅ **Подходит для:**
- Чистые, разделённые символы
- Печатный стиль (не cursive)
- Когда нужна интерпретируемость
- Маленькие модели (ограничения памяти)
- Визуализация сегментации

❌ **НЕ подходит для:**
- Cursive/connected writing
- Overlapping symbols
- Сложные layouts (дроби, степени с плохой сегментацией)
- Очень зашумленные изображения

---

## 💡 Советы:

1. **Начните с малых данных** (100-1000 samples) для быстрой проверки
2. **Проверьте сегментацию** на нескольких примерах перед полным обучением
3. **Используйте val_seg_acc** как индикатор качества сегментации
4. **Если val_seg_acc < 70%** - проблемы с сегментацией, не с классификацией
5. **M2 лучше для простых выражений**, M1 - для сложных sequences
